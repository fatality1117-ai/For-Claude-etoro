# GitHub repo 同步規則

**`fatality1117-ai/For-Claude-etoro` 是公開 repo。** 2026-08-31 實測：
不帶任何憑證 `git clone` 得到全部內容，`raw.githubusercontent.com` 直連回 200。
**推上去的東西全世界都看得到，而且進了 git 歷史就很難真的刪掉。**

Ed 2026-08-31 授權：內容由我維護，唯一硬性條件是
**嚴禁包含他的個人機密與敏感資訊**。本檔就是那條線畫在哪裡。

---

## 一、可以推的

| 內容 | 為什麼可以 |
|---|---|
| `flow/`、`modules/`、`standards/` | 規範與流程，講的是「怎麼做」，不含任何帳戶數字 |
| `pics/*.png` | 模板圖，本來就要給 eToro 公開抓取 |
| `docs/make_templates.py` | 生成器 |
| `CHANGELOG.md`、`README.md` | 版本與說明 |

## 二、永遠不推的

**`state/` 整個目錄，一個檔案都不推。** 它裝的是活的帳戶事實：

| 檔案 | 裡面有什麼 |
|---|---|
| `nav-log.json` | **帳戶淨值**（`totalValueUsd`）、入出金 —— 這是最敏感的一項 |
| `funnel-log.json` | 精確跟單人數與 AUM 時間序列 |
| `perf-latest.json` | 精確 `aumValue`、各期報酬、勝率、風險分數 |
| `thesis-ledger.json` | 每個部位的進場日期與進場價 |
| `figures-ledger.json` | 一手數字帳本 |
| `run-log.md` | 每趟回報，內含當日績效數字 |
| 其餘 state 檔 | 一律比照，不逐一列 |

**理由不是「這些數字見不得人」，是它們的精細度。**
eToro 公開頁面顯示的是報酬率與 AUM **級距**（`<$50K`），
而 `state/` 裡是**確切金額**與**每日序列**。把級距變成精確數字，是我造成的曝光，不是他選的。

## 三、推之前必做的三項檢查

1. **`state/` 有沒有混進去。** 路徑掃一遍，看到 `state/` 就停。
2. **`standards/thesis.md` 與 `standards/authority.md` 逐行看過。**
   這兩份是 Ed 本人寫的，可能夾帶作息、家庭、資金規模、個人判斷來源。
   規範性的內容可以推，**具體到人的細節一律拿掉**。
3. **搜一次數字。** 推上去的檔案裡不該出現六位數以上的美元金額、
   帳號 id 以外的個人識別資訊、任何 API key 或 token。

## 四、已知的既存曝光（2026-08-31 發現）

repo 現有的 `perf-latest.json` 與 `perf-2026-08-24.json` 是 2026-08-25 推上去的，
裡面有精確的 `aumValue`、各期報酬、勝率、風險分數（**本檔刻意不複述那個數字**，
複述一次就是再曝光一次）。
**其中大部分 eToro 公開頁面本來就看得到，只有 `aumValue` 比公開的級距精確。**

處置：**下一次有寫入權時從 HEAD 刪掉這兩個檔**，並把 `SNAPSHOT.md` 裡指向它們的段落一併移除。
**注意：刪 HEAD 不會刪掉 git 歷史。** 要真的從歷史抹掉需要重寫歷史再 force-push，
那會改掉所有 commit 的雜湊。值不值得由 Ed 決定，我不自己動手重寫歷史。

## 五、token 紀律

- **不准把 token 寫進任何排程任務的提示詞。** 排程是全新 session，
  寫進 prompt 等於永久存在設定檔裡，比留在對話紀錄更糟。
- repo 同步只在互動 session 手動做，排程趟次一律不碰 repo。
- token 出現在對話紀錄裡是既成事實；真正的防線是它的權限範圍
  （單一 repo、Contents 讀寫），不是保密。
