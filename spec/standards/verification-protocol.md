# 查證流程

2026-08-27 訂。起因：Ed 給的三組數字我有兩組宣稱「查不到」，
他用一般 Google / Gemini 就查到了。我比他有更多工具卻給了他更差的答案。

---

## 零、最嚴重的一條：不准把兩個來源黏成一個主張

**這是唯一會讓貼文變成假訊息的錯誤，優先於其他所有規則。**

2026-08-27 的兩個實例：

**一、稀土。** NdPr 我引**氧化物**價，鏑和鋱我引**金屬**價，
放在同一組讓讀者比較。兩者差一個量級。

**二、Amazon 機器人。** Nvidia 說的是「Amazon 將採用 physical AI 堆疊到
倉儲機器人隊列」。我另外查到「Amazon 已部署一百萬台機器人」，
然後把兩者寫成一句，等於宣稱有一百萬台要換上 Nvidia 堆疊。
**沒有任何來源這樣說過。那個連結是我造的。**

規則：

- 兩個數字要放進同一句比較，必須**同一個主體、同一種產品、同一個基準、
  同一個時間口徑**。任一項不同就不能並列。
- 想不出來哪一項不同，就是還沒查清楚，不要寫。
- **A 說的事實 + B 說的規模 = 我編的主張。** 一個來源支撐一個主張。
- 寫完每個並列或因果的句子，回頭問一次：**這個連結是誰做的，來源還是我？**

## 一、失敗的根因（不是「不夠努力」，是流程設計錯了）

**錯誤一：把查證範圍鎖在眼前那份文件。**
我抓了 Q2 FY27 的新聞稿和法說會逐字稿，在裡面找不到主權算力 300 億和
Physical AI 90 億，就下結論說「查不到」。

實際上：
- 主權算力 300 億 → **Q4 FY26 法說會**
- Physical AI 90 億 → **Q1 FY27 法說會，2026-05-20，Kress 原話**

**年化、TTM、run-rate 這類數字本來就是零星揭露的**，公司不會每季重複講。
它出現在「最後一次提到它的那場」，不是「最近一場」。

**錯誤二：搜尋的是容器，不是主張。**
我下的是 `Nvidia Q2 FY2027 earnings call sovereign AI revenue robotics
hyperscaler percentage transcript` —— 塞滿詞又指錯季度。
後來改用 `"physical AI" "$9 billion" Q1 FY2027`，**第一次就命中**。

**錯誤三：漏掉一個有名字的一手來源。**
逐字稿裡明講對帳表在 **CFO Commentary** PDF 裡。分部數字比新聞稿細。
我從頭到尾沒抓過那份。

**錯誤四：查不到就把球丟回給 Ed。** 正確做法是假設他對，去找出處。

同一個模式這兩天出現三次：GitHub 檔名（API 被擋 → 宣稱拿不到，
其實 `git clone` 可行）、貼文歷史（feed 參數用錯 → 宣稱帳號沒發過文，
其實二十幾篇）、以及這次。**一個工具或一個來源失敗，就宣告事情不存在。**

## 二、Ed 提供數字時的查證流程（照順序，不准跳）

**第 0 步：預設他是對的。** 我找不到，預設是我的搜尋方式不對。

**第 1 步：搜主張，不搜容器。** 精確詞組鎖數字與指標名。

**第 2 步：時間窗往回開四季。** TTM / 年化 / run-rate 一律回查最近四場。

**第 3 步：一手來源清單走完。**
1. 新聞稿
2. **CFO Commentary PDF** ← 最容易被我漏掉
3. 法說會逐字稿（含 Q&A）
4. 10-Q / 10-K
5. 前幾季的以上四項

**第 4 步：交叉來源。** 一手找不到才找有引用一手的二手報導。

**第 5 步：真的走完還是沒有，才回報。**
要寫**我查了什麼、用什麼字串、範圍到哪**，讓 Ed 能指路。

---

## 三、「查不到」不等於「不存在」

宣稱任何東西不存在之前，必須用**第二種方式**驗證：
- API 被擋 → 試 git 協定、試網頁、試第三方鏡像
- 端點回傳空的 → **先確認參數名稱對不對**（feed 是 `take` 不是 `pageSize`）
- 文件裡沒有 → 換時間窗、換來源類型、換查詢字串

## 四、累積，不要每次重查

`claude/figures-ledger.json`：每家公司、每個指標、數值、揭露日期、
出自哪一場、原話引用。查到新的一手數字當場寫入。
