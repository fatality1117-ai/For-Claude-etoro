# 模組規範 v2

**每個模組是一個角色。** 它有明確的契約、預算、失敗行為。
流程叫用模組，模組不知道流程長什麼樣。這樣加模組或換變體才不會動到流程。

---

## 一、兩種資料通道（MECE 的基礎）

**Run context —— 一趟之內的記憶體，模組之間自由傳遞。** 不落地。

**State 檔 —— 跨趟的持久記憶。每個檔案只有一個 writer。**
兩個模組寫同一個檔案，就是「改 A 壞 B」的來源。下表是唯一授權。

## 二、契約

每個模組檔一律包含這七節，順序固定：

```
## 職責        一句話。超過一句就是該拆成兩個模組。
## 契約        前置條件 / 後置條件。後置沒達成就是失敗，不准自認成功。
## 輸入        從 run context 或哪些 state 檔拿什麼
## 輸出        寫進哪個 state 檔（必須是上表授權的），放什麼進 run context
## 變體        a / b / c，各自處理什麼差異化需求
## 預算        正常呼叫數 / 上限。超過上限就停，回報超支
## 失敗行為    soft / hard / fatal 各自怎麼處理
```

## 三、失敗分級（三級，不准有第四種）

| 級別 | 意思 | 動作 |
|---|---|---|
| **soft** | 部分失效，產出仍可用 | 降級繼續，記缺陷，回報標黃 |
| **hard** | 這一件產出做不出來 | 放棄這一篇，其他產出繼續，記缺陷，回報標紅 |
| **fatal** | 再往下走會產出錯的東西 | **中止整趟**，回報，絕不硬寫 |

**重試一次 → 換備援 → 降級 → 才報失敗。** 順序不准跳，見 `flow/resilience.md`。
**不准靜默降級。** 用舊素材寫出一篇看起來正常的稿，比不發還糟。

## 四、規則

1. **變體同契約。** M4a 與 M4k 介面完全相同，只有內容規則不同。
   新增主題＝新增一個 M4 變體，不動流程、不動其他模組。
2. **模組不重述規範。** 撰文規則在 `standards/writing-rules.md`，模組只寫叫用哪份。
3. **模組不存變動資料。** 任何數字當場撈，見 `flow/pipeline.md` 鐵則 1。
4. **一趟只跑需要的模組。** 這是省資源的主要來源，出刊趟只有 3-5 個呼叫。
5. **每個模組回報自己的呼叫數與健康狀態**，M9 據此產出報告。

## 六、怎麼加一個新模組

1. 在 `modules/` 新增檔案，照七節契約寫。
2. 在本檔清單與 §1 的 writer 表各加一列。**新模組必須有自己的 state 檔，或不寫檔。**
3. 在 `flow/pipeline.md` §3 決定哪些趟次叫用它。
4. 需要新排程項就改 `flow/schedule.md`。
5. **不要動任何既有模組。** 需要動，代表介面切錯了，回頭重切。
