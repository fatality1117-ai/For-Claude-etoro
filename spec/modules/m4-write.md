# M4 WRITE — 撰稿

## 職責
把 M3 選中的素材，依主題變體的 brief 寫成一篇稿。

## 輸入
`state/signals.json` 選中的訊號、M1 的即時數字、`standards/thesis.md`、
`standards/writing-rules.md`、`standards/terminology.md`、
`standards/thinking-framework.md`。

## 輸出
草稿全文（純字串）+ 圖片 URL，交給 M5。

## 通則（十個變體都適用，寫在這裡不重複）
- **主軸是 Ed 的。** 我補事實，不換角度，不加「我的觀察」。
- **句法照 `standards/thinking-framework.md`：** 主詞在前、動詞明確、一句一件事、
  結論不藏。禁用 `it is` / `there is`。
- **報酬率當場從 M1 取**，`pnlPercent` 與 `avgOpenRate` 成對使用，文末標 snapshot 日期。
- **同層有負報酬的部位一併揭露。**
- 圖片 URL 逐字複製 `standards/image-templates.md`。

## M4c 的六段結構（2026-08-31 Ed 指定）

MONTHLY REVIEW 一個月只有一次，**它的讀者是已經在跟單的人，不是路過的人。**
所以它不是把 DAILY BRIEF 的數字加總，是一次對帳與交代。六段，順序固定：

1. **這個月的成績。** 月報酬、對 $SPY / $QQQ / $SOXX 的相對表現、當月最大回撤。
   數字當場從 M1 撈，標 snapshot 日期。
2. **持股表現。** 貢獻最大的三檔與拖累最大的三檔，各一行，報酬率與進場價成對出現。
   **賠錢的一定要寫**，只報喜是失信於 copier。
3. **這個月交易了什麼，為什麼。** 每一筆新開倉與平倉：標的、日期、當時的理由。
   理由要能對回 `standards/thesis.md` 的哪一層，對不回去的就誠實說是機會財或錯誤。
4. **好的事情 / 壞的事情。** 各自兩到三件，講事件不講情緒。
   壞的包含判斷錯誤、進場時機不對、部位過重、以及我沒做到的事。
5. **打算怎麼改善。** 針對第 4 段的壞事，一件對一條具體動作。
   **不准寫「會持續觀察」這種沒有動作的句子。**
6. **有沒有新看法。** 論點有沒有更新、哪一層的權重要調、下個月盯什麼。
   沒有新看法就寫「沒有，維持原論點」，那也是資訊。

結尾照 `standards/writing-rules.md` 的免責與署名。
**全文不預告未來交易動作**（`flow/pipeline.md` 鐵則）。

## 選變體的方式
`flow/schedule.md` 決定今天跑哪些變體。M4 不自行決定主題，
也不得建議跳過排定的主題（`standards/authority.md` 第一部分）。

## 失敗行為
素材不足 → **不准硬湊，也不准跳過**。改走 M4a 的安靜日路線，
並回報是哪個變體因為什麼素材缺口降級。
